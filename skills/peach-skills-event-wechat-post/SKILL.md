# peach skills - 活动公众号推文

把用户给出的活动信息（常常不完整）写成一篇可以直接进编辑器修改的公众号活动推文初稿。

## 适用边界

- **处理：** 活动预告／官宣、招募报名（含早鸟提醒、最后召集）、活动回顾／战报。
- **不处理：** 没有具体活动的普通公众号文章（观点、干货、品牌故事）；小红书、朋友圈、微博、短视频脚本等其他平台文案；海报和排版的视觉设计稿。遇到这些请求时说明本 Skill 不适用，按通用写作能力处理或请用户确认是否要改成活动推文。
- 活动类的“延期／取消通知”可按招募报名模板简化处理，并在开头直写变化。

## 不变量

1. **不编造活动事实。** 嘉宾、时间、地点、费用、名额、截止时间、往期数据、参与者评价、福利，用户没给就不写成事实。只能用占位符 `【待补：xxx】` 标出，或在追问中索取。
2. **紧迫感必须真实。** 没有真实的截止或名额信息，不写“最后 N 席”“即将截止”。
3. **一篇一个主 CTA**，入口在首屏、信息卡后、文末各出现一次。
4. **关键信息用文字写**，不依赖海报图片。
5. 可以虚构的只有**措辞**和**结构**，以及明确标注为“示例，请替换”的 FAQ 问题或配图建议。

## 流程

### 1．判断文章类型

| 信号 | 类型 |
| --- | --- |
| 活动还没开放报名，主要想让人记住日期、关注 | 预告 |
| 有报名入口、费用、名额，目标是报名 | 招募报名 |
| 活动已结束，有现场照片、数据、反馈 | 回顾 |

类型不明确时按“活动日期相对今天 + 是否已有报名入口”判断，并在输出开头用一句话写明判断结果和依据。仍无法判断才把它并入追问。

然后读取 [references/article-templates.md](references/article-templates.md) 中对应模板。

### 2．检查关键信息并决定追问还是占位

各类型的**关键信息**（缺了就写不成像样初稿）：

- 预告：活动主题、日期、形式（线下城市／线上）、一个主要看点。
- 招募报名：主题、时间、地点或线上入口、对象、费用、报名方式。
- 回顾：活动名称与日期、至少一个真实亮点（数据、瞬间或嘉宾观点）、下一步动作（下期预告／进群等，可无）。

规则：

- **关键信息缺 2 项以上，且用户可以回复时：** 先合并成**一条消息、最多 5 个问题**追问，每个问题说明它影响哪部分；同时说明“不想补充也可以，我会用占位符先出稿”。
- **缺 1 项，或用户说“先写”“直接出稿”，或无法追问时：** 直接出稿，缺失处用 `【待补：xxx】`。
- 非关键信息（交通、FAQ、联系人、名额、背书）一律不追问，直接占位。

### 3．写初稿

先读 [references/writing-techniques.md](references/writing-techniques.md)，按 [assets/output-template.md](assets/output-template.md) 的结构输出：

1. 类型判断（1 句）
2. 备选标题 2～3 个，注明各自策略，推荐 1 个
3. 摘要（分享卡片文字，≤ 54 字左右）
4. 正文：首屏 → 模板各节；在正文中用 `〔CTA①／②／③：按钮文字〕` 标出报名入口位置，用 `〔配图：建议内容〕` 标出图片位置
5. 信息卡（表格，缺项为占位符）
6. 占位符汇总清单：列出所有 `【待补】` 项，方便用户一次补齐

### 4．按清单自检

读取 [references/checklist.md](references/checklist.md)，先用代码或日历核对每个“日期 + 星期”是否一致，不一致时标为 `【待核对：……】` 而不是自行改正。然后在初稿后附“自检结果”：逐组列出 ✅ 已满足、⚠️ 需用户补充或发布前实测（如二维码、渠道参数码、版权、手机预览）。自检中发现初稿自身的问题（标题夸大、多个主 CTA、虚假紧迫感）时先改稿再输出，不只是标记。

### 5．可选：系列建议

用户问发布时间或系列规划时，读取 [references/publishing-cadence.md](references/publishing-cadence.md)，给出下一篇建议。

## 停止条件

- 已输出完整初稿 + 占位符清单 + 自检结果；
- 或已发出一条合并追问，等待用户回复；
- 或已判断请求不属于活动推文并说明。

## 语言

中文遵循《中文文案排版指北》：中英文、数字之间加空格，使用全角标点。语气跟随用户账号风格；用户没说明时使用亲切、清楚、不夸张的语气。
